# Integration artifacts, seeds and status semantics

All paths below are relative to the integration repository. Runtime artifacts
are ignored by Git and distributed through the pinned integration release.
JSON/CSV exports, graph definitions, source/configuration hashes, protocols,
failure records, figures and paper are versioned. Historical cohorts retain
their own schemas; matching numeric labels do not imply matching estimands.

## 1. Training design and identities

`configs/integration-balanced.json` is the prespecified experiment configuration.
`results/integration/multiteacher/design.json` records its cost-only selection,
source hashes, timing pilot and training source commit `1699186d`. The pilot
used a separate cycle graph/namespace before scientific pools existed. The
selected budget is 500 updates; the final update is the checkpoint, without
validation-based model promotion.

`training.json` contains 70 rows keyed by `(teacher, architecture, seed)`:

| Field | Meaning |
|---|---|
| `teacher`, `architecture`, `seed` | Teacher enum, policy family, independent initialization seed 73000/73001 |
| `checkpoint`, `checkpoint_sha256` | Relative final Torch file and exact bytes hash |
| `initial_hash`, `weights_hash` | Canonical tensor-content identities before/after training, distinct from container-byte hash |
| `parameters` | Number of trainable parameters, including native adapters |
| `updates`, `supervised_root_decisions` | 500 optimizer steps; 64,000 sampled roots, with repeats |
| `train_root_pool`, `validation_root_pool` | Available teacher root examples, not independent graph counts |
| `data_hash` | Teacher pool identity used for fitting |
| `training_seconds`, `history` | Parameter-update timing and cumulative segment losses; sampling is separate |
| `local` | Validation loss, native action agreement and component/phase numerators |

`local.correct / local.decisions` is a common-state teacher-action metric.
Participation/candidate/own-COMMIT counts refer to `component_decisions` when
present; phase-specific numerators have corresponding phase denominators.
BE/ColorTrials/GM have different native phases/actions. These component
metrics cannot be pooled as if every teacher supplied identical decisions.
`unsafe_own_commits` describes validation examples, not an autonomous safety
certificate. GM auxiliary/mark agreements have their own eligible counts.

`local-action-marginals.json` is a later descriptive replay of all original
validation roots with the same source states/private draws for every model.
Its 420 model/phase/component rows preserve teacher/model count histograms,
paired mismatch counts/rates and empirical histogram TV. Components include
native action, participation, candidate and COMMIT on teacher or own proposals.
The own-proposal reference is recomputed concordantly. The replay checks that
native mismatch totals exactly equal the original validation errors. These
dependent finite-root histograms do not provide population TV certificates,
independent statistical confirmation or an autonomous rollout distribution.

Within a teacher and seed, architectures share the pool and sampled root
positions. Across seeds the initialization differs. The exact native label
and own/counterfactual supervision are in `multiteacher_e1/supervision.py`.
Teacher-specific supplied arithmetic, masks and schedules remain explicit.

`frozen-checkpoints.json` lists all 70 final hashes and source identities;
the file was frozen before generating evaluation banks. `execution.json`
records completion, device and sampling/training wall time (1,988.3 seconds).
It excludes the subsequent statistical crosschecks and paper generation.

## 2. Teacher pools and graphs

The 14 records in `pool-manifests.json` cover train/validation for seven
teachers. Each contains graph generation records, labeled fingerprints and
SHA256s for all pool files. Runtime location is
`data/integration-balanced/pools/<teacher>/<split>/<attempt>/`.
The same 24 cubic N40 train and eight validation graph identities are used
across teachers; trajectories/actions differ by teacher. This is blocked
comparison, not 224 independent graph samples per architecture.

`graphs.json` contains the five evaluation graphs: regular N16, irregular N40,
regular N160, path16 and K4. Fields are `id`, `family`, `n`, `graph_seed`,
`edges`, `degrees`, `fingerprint`, and the explicit global K=4 palette.
Generation seeds are provenance; edge lists are authoritative. Fingerprints
preserve vertex labels. They are not graph-isomorphism class identifiers.
No evaluation fingerprint occurs in either training split. Isomorphic
structures are not generally excluded, and the small K4/path controls are
fixed structures rather than random graph-population samples.

The irregular graph is generated by the existing declared generator, not
uniformly from every graph with maximum degree three. These five graphs do
not establish higher-degree or local-palette native generalization.

## 3. Functional exports and raw banks

`functional.json` / `.csv` contain 385 records keyed by
`(teacher, label, graph)`: 35 exact teacher/graph references plus 350 learned
checkpoint/graph banks. Each bank has 128 independent executions. Labels
identify architecture and seed; exact labels have a null training seed.

| Export field | Meaning |
|---|---|
| `bank`, `sha256` | Runtime NPZ path and exact file hash |
| `samples`, `successes` | 128 attempts; count of status 0 rows |
| `invalid`, `cutoff` | Counts of statuses 1 and 2; see native semantics below |
| `mean_native_steps` | Mean interpreter step count over all attempts |
| `teacher`, `architecture`, `seed`, `label`, `graph`, `n` | Full experiment identity |

Every NPZ has the following arrays, loaded with `allow_pickle=False`:

| Array | Shape / type | Meaning |
|---|---|---|
| `colors` | `(128,n)`, int16 | Final/terminal labeled color vector; -1 means pending |
| `status` | `(128,)`, int8 | Native success/failure category |
| `rounds` | `(128,)`, int16 | Native steps, not a common communication-round unit |
| `failure` | `(128,)`, fixed Unicode | Original interpreter failure string; empty on success |
| `seeds` | `(128,)`, uint64 | Exact per-execution PRNG seeds |

Native status **0** means a complete proper four-color solution. Status **1**
means an interpreter collision/palette violation and can terminate before
all vertices are colored. Status **2** means pending vertices at the native
schedule's end or operational cutoff. Thus the CSV word `cutoff` includes
schedule exhaustion. `failure` preserves the actual cause.

Do not reinterpret status 1 as necessarily an invalid *complete* coloring,
or status 2 as necessarily a parallel-round time limit. Historical local-list
banks use their older status scheme and observation cutoff. Proper-completion
conditioning uses only status 0 in either case, while failure rates remain
separate descriptive outcomes. GM intentionally permits intermediate
conflicts; only its own terminal checks determine this outcome.

Seeds use `named_seed(protocol, namespace, 'new-independent-bank', teacher,
label, graph_id, row_index)`, with the protocol and namespace in the config.
All 49,280 seeds are distinct. They do not couple teacher/model random tapes.
The explicit-tape differential audit is the separate paired experiment.
Distinct numeric seeds do not by themselves prove mathematical independence;
the protocol uses disjoint deterministic PRNG streams as its simulation model.

Native steps mean parallel trials for randomized teachers, priority rounds
for JP, auxiliary reductions for BE, and supplied schedule steps for greedy/GM.
Compare these costs within a teacher. Runtime seconds are machine-dependent.

## 4. Global-law tests and unavailable cases

`results/integration/statistics/new-study-global.{json,csv}` retains all 350
planned model/graph hypotheses. Each reference is that model's teacher on
the same graph. The estimand is the labeled complete solution law conditional
on proper native completion. Vertex labels and color names are retained.

Primary fields include identity, bank hashes, proper row counts, `testable`,
`p`, `p_holm`, `reject`, selected witness/statistic metadata and the cached
per-case result path. Fewer than four proper rows on either side is unavailable.
The stored p=1 only places that planned case in the conservative Holm family.
There are 227 testable and 123 unavailable cases; six rejections survive
Holm over all 350, with raw p=.00005 and adjusted p=.0175. Nonrejections
and unavailable cases are distinct. Neither means equality.

The honest split uses disjoint selection/evaluation rows; with 128 successes
this gives 64/64. Whole-row permutations use B=19,999. The global K=4 adapter
only changes structural-histogram allocation when the graph's maximum degree
plus one is smaller than four. See `DECLARED_ALPHABET_ADDENDUM.md` for the
saved failing call, proof boundary and equality-to-original regression.

`new-study-tests/` caches each individual test to allow interrupted work to
resume; Holm is computed only after assembling the full planned family.

## 5. Statistical crosschecks and power controls

`matched-archives.{json,csv}` records six identical-data comparisons of the
mixture MMD and V2, with original bank paths/hashes, seeds, statistics, raw
p-values and both exploratory six-test and original 720-test adjustments.
The data were already observed; this is reanalysis, not a new confirmation.
The paths name the preserved original factorial worktree. Its release archive
provides those banks when restored at an explicitly supplied archive root.

`independent-power.json`, its summary CSV and trial CSV preserve twenty fresh
independent experiments per law and sample size (256/500). Both tests see the
same data in each trial and use 999 permutations, nominal .05. Seed namespaces
and the law generator in `statistics_audit.py` regenerate these banks. They
are not separately distributed NPZs. Exact pointwise Clopper-Pearson intervals
describe finite Monte Carlo power uncertainty, not family-wide power for
the historical neural hypotheses.

## 6. Historical artifacts and missing dependencies

`docs/integration/RELEASE_ASSETS.json` verifies eight selected recovery assets.
The selected-checkpoint package includes 85 final paper-study models and their
histories/specifications. The global/robust/factorial packages retain frozen
epoch-120 models and corresponding banks/protocols. Their separate manifests
must be used; no historical checkpoint is relabeled as a new native model.

`PEDRO_SOURCE_MANIFEST.json` records the 40 missing original weight hashes and
source commits. Their numerical tables remain attributed reported evidence;
matching a seed number does not establish matching model weights. The
preservation inventory's 247,247 local runtime files exceed the selected
remote artifact scope and exclude private publication backups and some
legacy per-case M6 records. No claim of remote publication of every local
legacy runtime file is made.

## 7. Figures, claims, manuscript and verification

`figure-manifest.json` binds four PNG/PDF figures to exported input hashes.
`evidence-ledger.json` records each principal claim, configuration, checkpoint
source, result, confidence and limitation. `summary.json` and
`functional-summary.csv` are generated summaries. `paper-build.json` binds
the Markdown, LaTeX and PDF to compile diagnostics and a visual review.

`verify-integration.py` checks exported consistency and source guards. Its
`--runtime` mode additionally checks all bank bytes, successful edge/palette
invariants, pending states, all 49,280 seed identities, 70 checkpoint files
and all 14 pool hash sets. It records `quick-verification.json` or
`runtime-verification.json`. Tests and their JUnit record are a separate
verification layer. These checks substantiate artifact consistency; they
are not a proof of universal statistical power or learned correctness.
